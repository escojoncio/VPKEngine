# GCN 64-bit float (f64) in the lifter

Every gfx7 f64 opcode of VOP1/VOP2/VOP3/VOPC lifts (`gpu/shader/gcn/src/lift_f64.inc`). A double is a VGPR pair
(low dword first) and a `vec2<u32>` in VPIR. Arithmetic is a soft-float library on `uint2`/`u64` shared by C++
and MSL, because Metal has no `double`:

* `gpu/shader/ir/src/f64_core.inc` is compiled twice: as C++ (`gpu/shader/ir/src/f64.cpp`, used by the VPIR evaluator and
  the tests) and, embedded in the binary, as MSL source (`vpir::f64::mslSource()`), which the MSL emitter prepends
  to a shader only when it contains an f64 op (`usesF64`).
* VPIR op `f64 <fn>, args..., mode` (`Op::F64`, functions in `VPIR_F64_FNS`: add mul fma min max ldexp rcp
  rcp_clamp rsq rsq_clamp sqrt trunc ceil rndne floor fract frexp_mant frexp_exp from_i32 from_u32 from_f32 to_f32
  to_i32 to_u32 cmp class div_scale div_fmas div_fixup trig_preop sat). The last operand is the MODE register,
  a constant when the lifter tracks it statically (`curMode`), else the live value.
* MODE bits honoured: 3:2 f64 rounding (all four modes), 7:6 f64 denormal input/output flush, 1:0 and 5 for
  `to_f32` (f32 rounding / denormal output), 8 DX10 clamp (NaN -> 0 in clamped results), 9 IEEE (signalling NaN
  handling of min/max). Default `0x1c0` (RNE, denormals allowed, DX10 clamp + IEEE).
* NaN: results are the default NaN `0xFFF8000000000000`; a NaN operand is returned quieted, first in source order.
  min/max follow the GCN rules (a quiet NaN loses against a number; -0 orders below +0, as the f32 forms).
* Inline constants: float constants are doubles (0.5, 1.0, ... and 1/(2*pi) = `0x3FC45F306DC9C882`), integer
  constants sign-extend, a literal is the HIGH dword. gfx7 VOP3 cannot encode literals.
* VOP3 abs/neg act on the high dword's sign, omod scales by 2^1, 2^2 or 2^-1, clamp saturates to [0, 1].

## Exactness

| group | status |
| --- | --- |
| add, mul, fma, ldexp, conversions, floor/ceil/trunc/rndne, compare, class, min/max, frexp | bit exact (tested against host `double`, ~12.7M differential checks) |
| fract | `x - floor(x)` clamped to `0x3FEFFFFFFFFFFFFF` as the hardware does; infinity gives NaN |
| rcp, sqrt | correctly rounded (hardware gives the same for the division sequence) |
| rsq | within 0.502 ulp (not the hardware's approximation) |
| div_scale / div_fmas / div_fixup | semantics derived so LLVM's f64 division sequence equals host division for 300k random pairs; corner cases of random operand chains differ in a handful of cases (budget of 5 in `gcn.lift.differential_f64`, `VPGCN_DIFF_ALLOW_MISMATCH`) |
| trig_preop | best effort (2/pi table, `gpu/shader/ir/src/f64_table.inc`, generated by `gpu/shader/ir/tools/gen_two_over_pi.py`) |

Not modelled: exception flags and the hardware's rcp/rsq/sqrt estimate bits (results are the correctly rounded
ones). Note for f32 `v_div_scale_f32`: the `rdn && qdn` overflow case is not special-cased there.

f64 atomics and DS f64 ops are the `isa` agent's: the library entry points (`vp_f64_add`, `vp_f64_min`, ...) and
the VPIR op are what they use for the arithmetic part.

## Tests

`vpir.f64.softfloat` (differential vs host double, bit exact for GCN specifics), `vpmsl.f64.library` (the MSL
library text and the emitter), `gcn.lift.differential_f64` (800 generated programs vs the reference interpreter),
golden lift `lift/cs_f64.*`.
